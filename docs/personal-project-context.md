# Personal project context

Personal workspaces can add role and preferences while shared records remain authoritative. Do not assume an agent invocation receives all personal files, instructions, Memory, or prior conversations.

Suggested explicit context:

```text
Registered project: <verified project ID>
My role: <TPM / engineering lead / sponsor>
Task: <one concrete request>
Canonical project home: <verified link>
Preferences: <format, language, timezone when relevant>
Constraints: draft only; use only the specified source scope.
```

Test direct agent chat and the intended personal-project invocation separately. Use a harmless unique phrase in the current conversation, a separate test file, and another conversation, then ask which context was actually accessible. Do not treat a fluent guess as proof. Compare project identity, connector account, source visibility, role-specific presentation and privacy isolation. Remove test markers afterward through an authorized reversible change.

If invocation or context transfer is unsupported, use direct agent chat with the explicit block above. Promote a personal insight to shared records only after review of its factual support and intended audience.
